## 1. 世界観テキスト

- 設定: 夜更けのサーバー室で障害が起きた。主人公(デバッガー)は、ログに潜って原因を探す。ログは迷宮、部屋は関数、通路は呼び出し。
- 用語: 稼働率(HP) / CPU(行動力) / ログ片(手がかり) / バグ票 / 写本(ログの控え) / 根本原因(ボス) / デグレ
- タイトル紹介文(2枠):
  1枠「深夜二時、サーバーが止まった。」/「原因は、ログの底に眠っている。」
  2枠「読む。絞る。直す。」/「バグの正体を見抜けば、夜は明ける。」
- 階導入(各1枠):
  - 1階「入口のログ。足跡はまだ新しい。」/「まずは、基本を押さえよう。」
  - 2階「呼び出しが深くなってきた。」/「ここから先は、症状がまぎらわしい。」
  - 3階「ログの最奥。ノイズだらけの部屋がある。」/「根本原因は、ここにいる。」
- ログ片の発見文(手がかり。汎用3種): 「古いログが残っている。時刻が合わない。」/「同じ行が何度も繰り返されている。」/「ここだけ、ログが途切れている。」

## 2. 死亡時「写本の書き直し」(稼働率0)

意味づけ: 潜行中のログは「写本」(控え)に書き写されている。稼働率が0になると写本が乱れ、最初から書き直す。失敗は消えず、シードが残る=再現できる。

- 1枠(暗転): 「稼働率が、ゼロになった。」/「ログの文字が、ほどけていく。」
- 2枠: 「写本が乱れた。」/「でも、書き直せばいい。」
- 3枠(シード表示と共に): 「同じシードなら、同じ迷宮。」/「今度は、原因に先に辿り着ける。」
- ボタン文言: 「写本を書き直す」(主) / 「タイトルへ」(副)
- 演出メモ(rio): 文字が1文字ずつ崩れて消える→ログ行が上から再描画される。ID案はscenario-effect-ids.mdに追記予定(要rioすり合わせ)
- 勝利時(参考): 「復旧を確認。」/「夜が、明けていく。」

## 3. バグ票文面

- 注意: leakはspec上症状が1つ。区別テスト用に症状2・3を追加(技術面OK)。
  - ①症状1〜3は同じ1つの正解(leak原因コード)に紐づく。判定ロジックは変えない。
  - ②症状3「再起動すると一時的に軽くなる」は文言のみ。再起動操作/演出は無し(実装追加は11/05初稿後にsota判断)。
  - 修正済み文言「確保した分を、きちんと返した。」はsota異論なし。shingo実装確認は11/04中。
- 出現文(バグ登場時、各1行):
  - 境界ずれ「数が、1つ合わない。」/ ヌル参照「何かが、空っぽだ。」/ 競合状態「結果が、定まらない。」/ メモリリーク「空気が、重くなっていく。」/ 無限ループ「…応答がない。」
- 再現成功: 「再現できた。これで直せる。」/ 再現できない時: 「まだ再現できない。直せない。」
- デグレ時: 「パッチが外れた。別の場所に影響が出る。」
- ボス(根本原因 票 #BUG-000): 件名「原因不明」。症状はノイズ(どの種類にも当てはまる文面)から始まる: 「ログが多すぎて読めない。」/「どのバグにも見える。」/「そもそも何も起きていない?」 → 3つ目以降で正体の手がかりが出る。撃破時「根本原因を特定。パッチを当てた。」
